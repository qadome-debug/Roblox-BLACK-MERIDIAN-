# Gate BM-020 — Secure networking

Status: **PASSED** on 2026-11-12 (local). Re-verified by CI on every push
(`tools/check-all.luau`).

## What the gate certifies

Every client request enters through one remote and one dispatcher that runs
the plan's validation sequence (3.2) in order, and no other path can mutate
server state from the client.

## Evidence

| Only allowlisted remotes exist          | `Security/Remotes.test` (create + audit, 5 cases); `tools/check-remotes.luau`; Bootstrap refuses to start on audit findings |

Total at gate time: 147 tests across 15 files, all passing;
`check-all` 13 steps green.

## Known limits (not blockers for the gate)

- `QuestChoice` and `TravelReady` have validators but no adapters yet; the
  dispatcher answers `UNKNOWN_ACTION` for them until BM-074 / BM-090.
- Replay protection is per session and in memory. Durable idempotency for
  rewards and progression is Phase B (BM-036 onward).
- The remote audit runs at server start. A remote created later by a plugin
  or injected script would need the periodic audit added in BM-132.
- Load behaviour of the limiter and replay cache under thousands of players
  is estimated, not measured; BM-131/133 measure it.

## Gate decision

Downstream gameplay adapters (BM-061, 064, 067, 068, 070, 074, 076, ...) may
begin. Each must register a validator and an adapter with the dispatcher and
add its cases to `src/tests/Security`.
