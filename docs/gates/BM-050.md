# Gate BM-050 — Reward integrity

Status: **PASSED** on 2026-11-15 (local, 274 tests, `check-all` green).
Re-verified by CI on every push.

## What the gate certifies

Permanent progression and rewards are durable, exactly-once, fenced to a
single writer, bounded in storage, and recoverable after any failure the
plan names (5.6, 10.2). No gameplay system can grant anything except through
`RewardService`, and nothing writes a profile except `ProfileStore` under a
valid lease.

## Evidence against plan 10.2

| Requirement                                              | Where it is tested                                                  |
| -------------------------------------------------------- | ------------------------------------------------------------------- |
| Stale lease owners cannot write                          | `Lease.test` takeover/fencing; `SaveQueue.test` "no lease, no write"; `ProfileStore.test` lease rejection; `Stress.test` stale-owner grants |
| Simultaneous servers cannot both acquire ownership       | `Lease.test` two-server acquisition; `FaultMatrix.test` lease faults |
| Repeated permanent grants do not duplicate               | `Receipts.test` same and cross-session; `RewardService.test`; `Stress.test` replayed sources |
| A lost write response does not cause a second grant      | `SaveQueue.test`, `ProfileStore.test`, `FaultMatrix.test` lostResponse at both boundaries |
| Pending reward intents recover correctly after restart   | `Receipts.test` crash-after-intent; `RewardService.test`; `FaultMatrix.test` crash cases; `ProfileService.test` recovery on join |
| Profile size overflow does not delete existing state     | `ProfileSize.test`; `SaveQueue.test` size rejection; `ProfileStore.test` |
| Permanent receipts survive migrations                    | `Migrations.test`; schema v2 migration keeps receipts; `ReceiptCapacity.test` archive preserves every claim |
| Corrupt profiles are not overwritten with empty defaults | `ProfileLoader.test` quarantine cases; `FaultMatrix.test` corrupt reads; `Repair.test` conservative repair |

Failure-mode table (plan 5.6): every row has a test in `FaultMatrix.test`,
`Lease.test`, `ProfileLoader.test`, `SaveQueue.test`, `ReceiptCapacity.test`
or `Stress.test`.

## Static enforcement

- `tools/check-persistence.luau`: DataStore writes only in `Lease` and
  `ProfileStore`; `GetDataStore` only in Bootstrap.
- `tools/check-deps.luau`: Services never depend on Network; only
  Bootstrap depends on Operations.
- `tools/check-contracts.luau`: no `any` in persistent types.

## Known limits

- Archive-aware duplicate detection relies on the archived set loaded at
  session start; archives are append-only and written by the owning server,
  so this holds, but a second server racing an archive during a lease
  takeover is covered only by the lease (BM-133 soak should exercise it).
- The reward catalog is empty: no canonical reward exists until the content
  inventory names them. Every path is exercised with test catalogs.
- DataStore behaviour is modelled by the fake; budgets, latency and real
  error strings are measured in BM-131/133.
- `ProfileLoader.isStoreFailure` matches error text heuristically; it is
  informational only (all thrown writes are treated as uncertain).

## Gate decision

Reward-bearing gameplay (BM-073 quests, BM-075 Waymark I, BM-081 items,
BM-088 collectibles, BM-094/095 Descent and boss rewards) may begin, each
through `RewardService` with catalog entries added in the same change.
